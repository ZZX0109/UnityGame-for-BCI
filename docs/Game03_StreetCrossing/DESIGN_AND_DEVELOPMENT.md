# Game 03 — First-Person Street Crossing｜第一人称半写实过马路完整设计与开发规格

版本：Design v1.0 · 2026-11-12  
仓库：ZZX0109/UnityGame-for-BCI · 分支：game03/street-crossing-fps  
定位：**第一人称、连续行走、半写实现代生活街道、安全过街决策游戏**。不是 Crossy Road 的跳格街机，不是驾驶或停车模拟，不是经过临床验证的康复系统。
目标：Windows PC、Unity 2022.3.62f3c1（仓库精确版本），沿用现有 Input Manager，保留原 Sokoban，不引入 EEG/UDP/网络服务。

> 本规格提出拟开发的游戏与验证要求，不代表已经完成 Unity 实机测试。交通周期与速度为可调的游戏原型参数，**不能冒充现实交通法规或特定国家的信号标准**。

## 0. 游戏主张与交互循环

玩家从住宅楼旁的人行道出发，前往马路对面的便利店/公交站；沿途需要主动左右观察、理解行人信号、判断车流与转弯风险、选择合理安全时机，安全通过斑马线。  
**成功**：玩家处于正确的人行路径，完成道路横穿并抵达可见目的地，不只触发任意道路端点。**风险/失败**：闯行人红灯、危险接近车辆、碰撞、超时等分开记录和反馈；碰撞采取暂停/淡出与重置，避免血腥或不必要惩罚性画面。

玩法不是“绿灯一亮就自动安全”，也不鼓励盲目冲刺或闯红灯拿高分。看见行人绿灯只是可以开始通行的重要前提之一；转弯车辆、未停稳车辆、遮挡等独立建模。首个教学关降低干扰，保证有合理可穿越窗口。

### 第一人称操作
| 键鼠 | 行为 | 规则 |
|---|---|---|
| WASD | 连续步行 | 与摄像机 yaw 对齐，不含飞行/跳格 |
| 鼠标 | 环顾街道，左右/上下观察 | pitch 限位、敏感度可调，摄像机无剧烈摇晃 |
| Shift | 快步走（按住） | 速度上限，禁止超现实冲刺；可选自动关闭 |
| E | 对环境提示牌/任务点确认（非过街必要条件） | 可达距离与视线检测 |
| Esc | 暂停/设置/返回 | 暂停后车辆和行人信号同步冻结 |
| R | 重新开始情境（确认） | 重置所有交通车辆与玩家位置、当前情境状态 |

默认成年人体验的参考：眼高约 1.60–1.68m，步速 1.2–1.5m/s，快走 1.7–2.0m/s，FOV 75–85°，鼠标灵敏度可调；视角不使用枪械式 bob、强动态模糊。可选慢速舒适模式。  
**观察行为**：玩家真实转动视角产生 camera yaw；左/右观察事件应通过朝向和持续时间等阈值捕获（原型可做为完成提示的交互条件，但不可作为真实道路安全能力的医学诊断）。不要仅仅按一个“观察”按钮伪造注意行为。

## 1. 游戏世界与场景蓝图

### 1.1 第一关住宅街区（首轮唯一完整街区）
场景：StreetCrossingScene.unity。小型生活街区，**单处有行人信号的斑马线**、两方向机动车道、可走人行道、住宅楼立面、便利店、公交站、树池/路缘/标线/人行信号、机动车信号、少量行人 NPC。  
玩家从住宅区一侧走向公交站方向；道路两侧需要一段足以调整观察站位的人行道，而不是把玩家直接放在路沿上。

模块与建议尺寸（米；按素材最终校验）：
- 每方向单车道宽 3.0–3.5m，双向道路约 6–7m；路边缘与斑马线无高度误差穿插
- 双侧人行道宽 ≥ 2m；斑马线宽约 3–4m；路沿约 0.10–0.15m，行人通行口使用缘石坡道
- 50–100m 可见街段，两侧道路闭环生成/回收车辆，背景建筑作为远景
- 建筑比例真实，建筑入口与公交候车设施可辨识；不用大地图或整座城市
- 所有道路路径、停止线、斑马线与行人区域使用明确 gizmo；碰撞区域不得与视觉不符

**方向设置**：默认用一套明确的车道左右交通配置（可在场景配置文件切换），但**首版不假定符合新加坡或中国大陆真实交通法规**。明确车辆行驶侧、车道方向、停止线与各相位冲突关系，确保看起来与车道/信号一致。

### 1.2 可交付的场景视觉
风格：stylized realism，像生活化的城市街道而非方块玩具或贴图平面。路面轻微颗粒、磨损、标识与立面细节；车辆不必超高面数，但比例、车灯、轮胎和阴影可信。树木、垃圾桶、车站亭、店铺招牌有少量差异化素材。  
光照：晴天上午的柔和日光、适度阴影、反射探针和基础环境光；首版不做昂贵雨天水面和逐帧高负载阴影。  
角色：第一人称无需建完整玩家身体；至少少量 NPC 走路、等待和过街动画，不出现行人穿车、穿墙等明显瑕疵。  
可读性优先：交通灯即使远看也能够清楚辨认状态，配套图标/轮廓，不仅凭红绿色差异判断。减速区/停止线和目的地标识清晰。画面不鼓励玩家盯着 UI 而忽略环境。

### 1.3 交互系统和界面
- HUD 默认只有目的地、可选距离、任务进度、小型辅助提示。不要让巨大的“红灯停/绿灯行”字样遮住斑马线。
- 到达路沿时，可提示“观察左右车流和行人灯”；可选教学层每关第一次出现；完成教学后仅在错误操作时给予反馈。
- 过街过程中不以文字不断弹窗打断镜头；短促环境音/路口音与画面信号相符。
- 主菜单：真实街道背景 + 开始/关卡/设置；暂停与结算使用简洁半透明卡片。
- 结算展示任务是否安全完成、等待时间、观察动作、违规事件和危险接近（如有）；避免单纯奖励最短时间。

## 2. 交通逻辑：游戏正确性核心

### 2.1 统一路口信号控制器
**单一权威 IntersectionController** 控制当前阶段及剩余时间，TrafficSignalView 只能渲染阶段，VehicleController 只能根据明确的“是否允许通行/停车目标”行动，CrossingEvaluator 查询同一个阶段状态。禁止用三个互不关联的 Coroutine 让信号各走各的时间。

初版六相位配置（示例，独立 ScriptableObject 配置）：

| phase | 示例时间 | 行人信号 | 冲突机动车 |
|---|---:|---|---|
| VehicleGreen | 15s | 红 | 可通行 |
| VehicleAmber | 3s | 红 | 遵守停车决策 |
| AllRedBeforeWalk | 2s | 红 | 不再允许新车进入 |
| Walk | 12s | 绿 | 对行人横穿方向停止 |
| WalkFlashing | 5s | 闪烁/清空 | 对行人横穿方向停止 |
| AllRedAfterWalk | 2s + 条件清空 | 红 | 等待横道清空再放行 |

**重要安全语义**：WalkFlashing 用于已在斑马线上的行人完成穿越，默认不鼓励新的行人进入；真实规则依地区而定。若玩家在清空阶段还在道路内，模型应正确阻止冲突车辆提前放行，而不是强制玩家失败。为了避免永远卡住，添加可配置保底超时、异常处理与调试输出，但不能以撞人作为清空策略。

每个相位有 Enter/Tick/Exit、固定阶段配置和状态变更事件；Unity 的 Time.deltaTime 适合单机 UI 与游戏演示，但独立时钟及固定 seed 可提高回归测试确定性。暂停时世界时间与相位同时停下。

### 2.2 机动车行为
VehicleTrafficManager 负责受控生成与回收：指定车道方向、可复现 seed、车辆预制体/速度、头距、最大同时车辆数量、停车线距离、转弯路线与车队防追尾。  
VehicleController 状态：Cruising → Approaching → Braking → Stopped → Starting → Cruising；出现前车/行人/停止线障碍时会重新进入刹车状态。对红灯、新进路口等冲突需有明确优先级。

**基础制动模型（可先用运动学，不需要 WheelCollider）**：
- 距停车线距离 d、当前速度 v、舒适制动 b（m/s²），估算停车距离 d_stop≈v²/(2b) + 反应裕量；
- 在可控距离内减速，要求停在停车线前；不瞬移、不瞬停；不能启动时穿过尚未清空的斑马线；
- 车道可用 waypoint/spline，按世界坐标道路行进；不同车道速度有小波动但不随机违反交通信号；
- 首轮禁止车辆转弯穿过玩家过街路径；将转弯引入关卡 3，必须实现让行。

车辆碰撞与行人安全：只有真实碰撞检测触发事故；“危险接近”在时间到碰撞、最小距离和横道区域附近判定，不应把每辆停在路口的车算成危险。车辆冲突处理有上限防止阻塞/穿车；行人已进入横道时限制车辆进入冲突区。

### 2.3 NPC 行人
NPC 行人状态：WalkingOnSidewalk、WaitingAtKerb、Crossing、Arrived；可用 NavMesh/路点组合。必须跟随同一信号状态机；有等待区与通行时的非碰撞/避让规则。首轮 2–5 人即可。  
行人不在玩家正前方挤成不可通行墙；不要用 NPC “闯红灯”做模糊示范。后续情境可以有错误示范，但应明确标识与难度条件。

## 3. Player/安全通行判定

### 3.1 第一人称 CharacterController
移动采用 CharacterController（人工重力与地面检测），摄像机 yaw 跟随移动、pitch 限幅，禁止向路面穿模；路沿坡道可通行，车体碰撞不可穿越。速度在 Update 中结合 deltaTime。默认无跳跃，不鼓励通过跳跃规避交通风险。

### 3.2 多区域检测
**区域**：ApproachZone、KerbWaitingZone、CrosswalkEntryZone、RoadwayConflictZone、CrosswalkExitZone、DestinationZone。  
CrossingEvaluator 只记录真实区域进入/退出，不依赖单个终点碰撞器判断安全过街。  
应记录：CrossingStarted、SignalAtEntry、LeftLook/RightLook、VehicleConflictAtEntry、NearMiss、Collision、SafeArrival、CrossingEnd。若进入时为红灯，标记规则违反；如果在合理合法的 Walk 阶段进入但中途灯转为清空阶段，不应直接判成红灯闯行。

### 3.3 独立评分与进度
- 主目标为 SafetySuccess：成功到达目的地、无碰撞且根据关卡的安全通行规则完成；
- 可评价指标：观察完整性（左右检查行为）、违规次数、危险接近次数、最长等待、完成时间；
- 可选 3 星：安全完成、规范观察、无危险接近；**绝不以抢时间/冲红灯奖励高分**。
- 对于教学任务，允许首次错误进入有明显反馈和重新尝试，失败动画短且非惊吓。
- 调试信息需要呈现“为什么不安全”（信号错误、车辆未停、车距不足等），别只写失败。

## 4. 关卡与内容递进

**首个里程碑只做 1 个街区 + 3 个情景配置**，保留同一套 Prefab 与地图。正式目标 5 个情景，后续再加独立 T 字/十字路口。

| Level | 场景变化 | 主要行为与失败模式 |
|---|---|---|
| S01 便利店 | 双向车道、简单绿灯窗口，2 辆车循环 | 教学看信号、等待、斑马线通行 |
| S02 公交站 | 车密度增加，部分到路口后停车 | 同时观察双方向车流、判断车辆实际停稳 |
| S03 十字路口 | 新增转弯车路径（可以扩大路口） | 判断转弯车冲突、确认让行 |
| S04 遮挡路口 | 停靠车辆或绿植降低部分视距 | 主动改变观察站位，不从盲区横穿 |
| S05 放学时段 | 学校附近、更多 NPC、速度变化 | 多目标分心与综合过街，不采用不可避免碰撞 |

每个情景有稳定 scenarioId、seed、交通流密度、车辆速度区间、相位时长、初始灯状态、目的地、行人数量、提示策略、危险事件配置、重开是否复现。保存和解锁按稳定 id 而非数组位置。

**难度不只是车速与数量**；更重要的是可观测风险、可合理判断的通行窗口和环境遮挡。每个场景必须存在一条规则一致、足够完成的安全通行路径。用自动模拟找“有无安全窗口”，并由真人至少完整游玩验证。

## 6. 最小可行实现算法与 Unity 技术

**行人控制**：CharacterController + Cinematic camera constraint；PC 输入通过 Input.GetAxisRaw，Game UI 对设置作持久化。  
**机动车路径**：车道中心线与一组路点/样条点；不使用导航网格代替车辆的车道规则；运动学恒定或加减速，不在碰撞区瞬移。  
**交通信号**：ScriptableObject IntersectionPhaseTable 定义各阶段时长与冲突矩阵，状态机内统一 Tick；信号视图只是灯的材质与图标。  
**车辆探测**：前方射线/BoxCast 判断车距和障碍，停在明确停车线；流量通过 seed 决定初始车辆生成和间隔；车离开范围后回收 Prefab 对象池。
**路口安全**：CrosswalkPriorityManager 在人行窗口和玩家已进入斑马线时维护冲突区授权；对红/黄灯进入路口的既有车辆要求驶出清空区后才进入新相位。  
**观察记录**：Camera yaw 在 kerb waiting zone 时累计左右视觉扇区内观察持续时间，独立输出 observation coverage；需要对“向左/向右看了”与“真的看见车辆”作区分，不能把眼球注意力简单等同摄像机朝向。
**事件驱动**：事件/接口为主，避免 Update 大范围反复 FindObjectOfType；车辆状态缓存和同步收敛；Unity 物理检测与路线规划分层。
**时间**：交通与游戏世界时间由统一可暂停时钟推进；测试可注入模拟时钟，使过街窗口与车流可重复。
**场景结构**：
StreetRoot / RoadSystem / Crosswalk / IntersectionSignals / VehicleSpawnPoints / VehicleRoutes / Sidewalks / StreetProps / NPCs / PlayerRig / Managers / Canvas。
动态关卡更改使用场景配置，不为每个 S0x 重复拷贝整个 Unity Scene。

## 7. UI、生活氛围与声音

**主菜单**：静态/轻动画街景背景，侧边清晰按钮开始/选择情景/设置/退出；没有过度赛博科技元素。  
**HUD**：目的地、“前往公交站”短句、可选观察提示；信号灯信息主要由世界物体表达，教学提示浮层透明而不遮挡。
**结果屏**：是否安全完成、进入时信号、是否左右观察、危险接近、用时；附简要可解释反馈，如“行人绿灯有效，但转弯车未停稳”。  
**音效**：日间交通环境音、轮胎与发动机、行人提示音、环境氛围、脚步、按钮点击；考虑重复性和听力无障碍，不把声响作为唯一安全信息。
**设置**：鼠标灵敏度、FOV、声音、无镜头晃动、图形质量、字幕字号、颜色区分辅助、全屏/窗口。  
**性能建议**：初版 1920×1080 Windows 中端 PC 目标 60fps；同时测 1% low、场景加载、内存和 NPC 数量变化，不以 Editor 单次 FPS 替代构建实测。使用 LOD、Occlusion Culling、简单阴影和有限的车人数量；渲染管线沿用仓库现状。

## 8. 开发里程碑

**M0｜街区灰盒与玩家（1–3 天的任务量级）**：一个住宅街区、斑马线、停止线、PlayerController、可视交通灯与任务点。能正常走路、观察、抵达目的地，无交通行为时不计分。

**M1｜交通可信闭环（3–5 天）**：统一相位状态机、双向车辆停车/起步/等待、禁止冲突放行、斑马线状态、S01 教学。模拟事件 log 证明车辆不会按绿灯忽略正在穿越的行人。**本项目最优先交付。**

**M2｜可玩三关（3–6 天）**：S02 车流判断、S03 转弯让行、路口危险评估、失败/重置、菜单和初版 UI、最小行人 NPC。场景材质统一，不要求完整艺术精品街区。

**M3｜正式视觉与五情景（3–6 天）**：S04 遮挡、S05 人流、路边环境细节、行为与音效、存档、全分辨率/舒适度校验、Windows Build。

任务量级不是后台交付承诺；交通数据、资产授权和场景实机调参可能改变实际投入。

## 9. 验证与回归测试（需真实证据）

**EditMode**：
- 6 相位有明确转换序列、时长边界准确；暂停不推进；
- 同一时刻冲突车道和行人不同时获放行授权；从黄灯/清空期到绿灯不瞬开；
- 制动模型在可控条件下车辆停在线前，前车停车不会出现穿车；
- 车辆固定 seed 同序列生成，重开同局可复现；
- CrossingEvaluator 区分红灯进入、绿灯进入后相位改变、停在线前/进入后灯变换；
- 视角观察指标在满足指定朝向/持续时间时记录，无观察不自动成功；
- 危险接近与真实碰撞、目标抵达事件不会重复计数；
- 配置关卡必须有足够的可穿越窗口和合理目标。

**PlayMode + 人工**：
- 玩家在路沿、斑马线、公交站之间正常走，无法穿车、穿房；
- 红灯等待/绿灯进入/步行中相位变化均符合约定；
- 车驶近红灯渐进停车、排队与起步、在路口不能突然瞬移；
- 行人已入斑马线时，冲突车辆等待；拥堵时不会永久僵死；
- 失焦暂停，重入后时钟/交通/玩家同步恢复；
- S01–S03 人工分别通关；R 连续重置、反复场景切换无重复车辆/隐藏物体；
- 第一人称转头视角舒适，左右道路可观察；车辆速度感合理；
- 1280×720 / 1366×768 / 1920×1080 / 1280×1024 的 HUD 与菜单无文本溢出；
- Windows x64 构建运行，正常进出关卡，平均 60fps 目标并记录 frame time/GC spikes；
- 场景模型、音频、车辆素材和字体授权可追踪；真实测试 XML、日志和视频与提交 SHA 对应。

**人工体验问卷**：玩家是否清楚何时可进入、为何有风险、为何失败，是否有视觉遮挡或眩晕。将其视为游戏可用性反馈，不作临床效果结论。

## 10. 典型风险与规避

1. 机动车信号与行人信号分离 → 统一授权和冲突矩阵，禁止多个自由计时器。
2. 随机车辆撞人但无可规避路径 → scenario seed + 有保证安全窗口 + 自动运行仿真。
3. 玩家绿灯进入后变红仍判违规 → 判定以进入时相位、位置和完成时间分开计算。
4. NPC/车辆穿透 → 路口冲突区授权、车辆队列、路点与 Collider 一致。
5. 场景过大导致低帧率 → 一个街区优先 + LOD、对象池和少量行人。
6. 以“谁跑得快”作为成功 → 安全优先，通行时间次要，不鼓励闯灯。
7. 真实生活写实要求膨胀 → 先交通逻辑和可读性，再资产细节；不加入无关完整城市。
8. 用户当前 Sokoban 项目回归 → 独立 Scenes/asmdef/Save/BuildOutput，不能改动旧模块和 main。
