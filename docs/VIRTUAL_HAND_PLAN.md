## 3. 建模与画面要求

### 3.1 模型与材质

- 使用 Blender 制作自然的人体双手，包含短前臂，避免手腕截面直接悬空的展示效果。
- 采用 MakeHuman 官方 CC0 核心人体网格为基础，由 GLM 完成手部提取、整理、细化、绑定和材质制作。
- 最终必须是连续蒙皮的自然人手，具有清楚的掌形、虎口、指甲、指根连接和关节轮廓；不以胶囊、方块或机器人关节手作为最终成果。
- 重点处理拇指对掌、五指长度比例、指根连接、握拳时的皮肤变形和捏握接触位置。
- 每只手约 1 万～2 万三角面，使用 2K 贴图、Built-in Standard 材质、柔和灯光和接触阴影。
- 皮肤细节与指甲高光应克制自然，不能依靠过强曝光或纯色材质掩盖变形问题。
- 优先利用官方 CC0 皮肤贴图并保留正确 UV，可程序化补充细节；不默认采购外部资产包。
- 保存可编辑 `.blend`、导出 FBX、材质和贴图。`.blend` 放在 `ArtSource`，Unity 导入和运行不依赖安装 Blender。

### 3.2 骨骼与动作

- 通过实际骨骼和蒙皮变形驱动动作，不以几张静态模型切换代替。
- 制作张手、握拳、松开、五指分别屈伸、拇食指捏握及持物姿态。
- 拇指使用独立对掌控制；左右手的朝向、弯曲方向和镜像关系正确。
- 手指屈伸应有自然过渡，限制关节范围，避免明显自穿插、指根塌陷和拇指扭曲。
- 提供默认操作视角及可旋转观察的模型展示视角。

### 3.3 美术验收门槛

- 至少提供掌心、手背、侧面、握拳、捏握、双手持物六组可见画面。
- DHS 与 Codex 均需检查静态外观及实际动画。
- 探测图过黑、取景错误或模型被遮挡时，应重新输出，不能据此认定美术通过。
- 接口数值通过不能替代外观验收；明显变形或穿插必须调整后才能交付。

## 4. 数据读取与姿态回放

### 4.1 Ninapro DB8 首批数据

- 首批使用健康被试 S1 的 A3 文件：`S1_E1_A3.mat`。

- 按官方 CyberGlove 传感器布局建立映射，记录缺失传感器、联动关节和显示校准的处理。

- 数据手套佩戴在左手；显示右手镜像时，界面与来源信息明确标记“镜像”，不能当作真实双手运动真值。

- 按原始时间顺序回放，导出为约30～60Hz的可管理姿态帧，保留被试、动作片段和采样时间来源。

官方资料：

- [DB8 数据与说明](https://ninapro.hevs.ch/instructions/DB8.html)
- [S1/A3 单文件](https://ninapro.hevs.ch/files/DB8/S1_E1_A3.mat)

### 4.2 数据与预测的区别

- 手套轨迹用于连续姿态展示；EEG 分类用于整体手部意图，不把两者合称为“脑电直接解码全部关节”。
- 单指屈伸和捏握可由手动控制或姿态数据展示；首版 EEG 模型只识别静息、左手、右手、双手四类。
- 所有导出保留数据来源，手工样例、标签回放、手套回放和真实预测回放分别标识。

## 5. 真实 EEG 离线解码

### 5.1 数据与划分

- 使用 PhysioNet EEG Motor Movement/Imagery Dataset（EEGMMIDB），首批被试 S001、S002、S003。
- 为每名被试分别训练个体模型，不把此阶段结果称作跨被试或患者验证。
- 单手运动想象使用 R04、R08、R12；双手运动想象使用 R06、R10、R14。
- 单手 run 中 T1 为左拳、T2 为右拳；双手／双脚 run 中 T1 为双拳、T2 为双脚，双脚事件必须排除。
- T0 为静息。必须结合 run 解释事件，不能将所有 T1/T2 全局映射为同一个手动作。

| 数据用途 | 固定 run |
| --- | --- |
| 训练 | R04、R06 |
| 验证 | R08、R10 |
| 最终测试 | R12、R14 |

不得随机打散相邻或重叠时间窗造成数据泄漏；测试数据不得用于拟合变换、校准或超参数选择。

官方资料：[PhysioNet EEGMMIDB](https://physionet.org/content/eegmmidb/1.0.0/)。

### 5.2 首版基线

- Python 使用独立虚拟环境，依赖 NumPy、SciPy、MNE、scikit-learn、joblib；首版不引入深度网络训练。
- 采用因果8～30Hz滤波、共同平均参考、事件后0.5～2.5秒分析窗。
- 使用 CSP（6个分量）＋收缩 LDA，固定随机种子42。
- CSP及其他需拟合步骤仅使用训练集。
- 以0.6作为首版低置信度阈值，报告对应覆盖率；模型概率不宣称为已校准的临床置信度。
- 提供平衡准确率、按“静息／左手／右手／双手”固定顺序的混淆矩阵、低置信度拒绝比例和被试分别结果。
- 用户选择“跑通并如实展示效果”，不设必须达到的准确率，不通过替换标签获得表面正确结果。
- 预测时间不得早于对应分析窗口结束，保留实际错误和拒绝结果。

### 5.3 导出与真实性

- 真实预测与标注参考分别导出，Unity 预测模式只读取预测指令。
- 标注用于对照和评估，不能在动作错误时自动补正。
- 标签回放以独立模式呈现；演示脚本也必须标为手工或脚本来源。

## 6. 统一接口与播放行为

### 6.1 动作来源接口

定义 `IHandMotionSource`，使手动操作、手套姿态回放、标签回放和预测回放共用驱动入口。

接口包含：

- `FrameReady`：输出一帧 `HandMotionFrame`。
- `IsPlaying`、`Position`、`Duration`：播放状态和秒数。
- `Play()`、`Pause()`、`ResetPlayback()`：播放控制。

模型驱动不直接读取数据集原文件、键盘或分类器训练状态；数据来源不直接操作场景物体。

### 6.2 JSONL v1 动作帧

UTF-8 编码，每行一个 JSON 对象，字段与共享的 `HandMotionFrame.cs` 一致：

| 字段 | 含义 |
| --- | --- |
| `version` | 格式版本，首版为1 |
| `time` | 从回放起点开始的秒数 |
| `duration` | 本帧有效持续时间，必须大于0 |
| `intent` | `rest`、`left`、`right`、`both` |
| `confidence` | 0～1的模型概率或对应来源的有效值 |
| `source` | `manual`、`glove`、`labels`、`prediction` |
| `subject`、`run` | 被试与记录来源 |
| `leftJoints`、`rightJoints` | 可选的20个归一化姿态控制值 |

姿态数组按拇指、食指、中指、无名指、小指排列，每指4个控制值：

- 拇指：CMC屈伸、MCP屈伸、IP屈伸、对掌。
- 其他四指：MCP屈伸、PIP屈伸、DIP屈伸、外展。

值域为0～1，实际到骨骼的映射由手部姿态配置完成。这是可视化控制约定，不能称为20个实测关节角度。没有姿态数组时，以整体意图驱动预设手姿。

### 6.3 播放与异常处理

- 支持加载、播放、暂停、继续和重新开始。
- 播放和任务使用同步时钟，暂停时手部路径与任务推进同步停止。
- 输入时间空隙或帧到期后不无限沿用旧意图，持物状态按任务保持规则处理。
- 对未知标签、非有限数值、错误长度等损坏帧给出可见错误，不误触发抓取或释放。
- 重置清理姿态、持物关联、时钟、任务阶段和数据来源状态。
- 切换来源不得混合两条输入或遗留物体挂接。
- 中文界面显示当前来源、任务步骤、识别结果和辅助状态，播放控件与旋转镜头操作不冲突。

## 7. 双手任务与交互

### 7.1 双手搬运盒子

1. 双手沿预设辅助轨迹到达抓取位置。
2. 双手建立抓握并共同持物。
3. 沿预设路径搬运到目标区。
4. 目标区内且当前步骤允许释放时，持续静息触发放下。

### 7.2 左右手交接方块

1. 左手拿起方块并移至交接位置。
2. 右手到位并建立稳定抓握。
3. 确认接手持稳后，左手才释放。
4. 右手搬运并在目标区放下。
5. 同样支持右手向左手的反向交接。

### 7.3 任务控制约定

- 空手静息时停止动作；持物静息时保持抓握，不立即掉落物体。
- 只有进入指定放置区、任务阶段允许释放且静息持续满足条件时才放下。
- 接手握稳之前，原手始终保持持物；输入中断或低置信度不能造成交接中途无人持有。
- 抓握在接触后保持，不要求分类标签逐帧持续相同。
- 错误或不匹配预测按真实识别结果呈现，任务可以等待或记录失败，不自动补成正确指令。
- EEG 控制的是手部激活和整体抓握意图；到达、搬运路径以及交接确认后的原手松开属于任务辅助，界面明确显示。
- 使用统一物体持有状态；避免双重挂接、刚体与 Transform 同时争夺位置、物体瞬移或重置后悬空。
- 采用预设抓握点和贴合道具的手姿，避免手指深入盒子；首版不制作逐指刚体抓取系统。
- 用已知手动／脚本指令单独测试任务机制，再用真实 EEG 预测回放观察实际表现；二者结果分开记录。
